# تحویل پروژه هم‌نوا به چت یا توسعه‌دهنده بعدی

این سند مستقل است؛ ادامه‌دهنده نباید فرض کند تاریخچه چت قبلی را دیده است.

## وضعیت جدید نسخهٔ ۰٫۲

نسخهٔ قبلی با ورود رسمی صاحب پروژه روی Hosting منتشر شد و کاربر آن را باز کرد. این نسخهٔ جدید باید دوباره با `bash scripts/deploy-firebase.sh` منتشر شود؛ commit یا push به‌تنهایی سایت را به‌روز نمی‌کند.

ورود وب اکنون `Persistence.LOCAL` است؛ بستن اپ نباید ورود را مانند نشست موقت پاک کند. هنگام تغییر حساب، پنجره‌های خصوصی بسته می‌شوند. یادداشت‌ها در پوشه‌های روزانه‌اند. ضبط فایل و تبدیل گفتار دو حالت مستقل‌اند؛ برای Safari اول MP4/AAC امتحان می‌شود و خروج از صفحه ضبط را متوقف می‌کند. فایل صوتی واردشده حداکثر ۲۰ مگابایت و فقط محلی است؛ تبدیل فایل به متن نداریم. رفع واقعی مشکل میکروفون آیفون هنوز باید بعد از انتشار روی دستگاه کاربر تأیید شود.

رسیدها با دوربین یا انتخاب عکس به تراکنش وصل می‌شوند: حداکثر سه JPEG فشردهٔ ۲۰۰ کیلوبایتی، ذخیرهٔ مالک‌محور در `users/{uid}/receipts/{id}` و اتصال اتمی با `receiptIds` تراکنش. تصاویر بین دستگاه‌ها همگام‌اند؛ صداها همچنان فقط محلی‌اند. مشاهده/دانلود عکس، PDF تکی، PDF ماه و PDF همهٔ رسیدها در تنظیمات پیاده شده است. Storage، حساب پرداخت، OCR پولی یا سرویس صوتی پولی فعال نشده است. قواعد قدیمی اطلاعات جدید رسید را قبول نمی‌کنند؛ Rules و Hosting را با هم منتشر کن.

بررسی محلی: analyze، ۱۶ تست Flutter/PDF، ۱۷ تست مرورگر و ۵ تست Rules و ساخت وب پاس شدند. تست مرورگر واقعی با میکروفون مجازی و عکس نمونه انجام شد؛ دادهٔ زندهٔ کاربر استفاده نشد. راهنمای پذیرش در [RELEASE-0.2.fa.md](RELEASE-0.2.fa.md) است. بخش‌های قدیمی‌تر این سند شواهد نسخهٔ پیشین را شرح می‌دهند.

## هدف و محدودیت‌های صاحب پروژه

ساخت یک وب‌اپ ژورنال فارسی، خلوت اما با طراحی خاص و قابل معرفی در رزومه.
کاربر از آیفون و مک استفاده می‌کند، تایپ را دوست ندارد و ورودی اصلی را صدا
می‌خواهد. چند کاربر باید بتوانند حساب مستقل داشته باشند. بودجه صفر است؛
سرویس صوتی پولی، اتصال حساب پرداخت و خرید دامنه در برنامه فعلی جایی ندارد.
بعداً امکان توسعه به اپ iOS/Android و رابط آلمانی مطلوب است. بخش مالی باید
کاملاً مستقل از ژورنال باشد و هر پیشنهاد مبلغ قبل از ذخیره تأیید شود.

## نام و محل کد

- نام محصول: هم‌نوا / Hamnava.
- مخزن عمومی: https://github.com/Rezatajali/hamnava
- شاخه اصلی: `main`.
- نام پکیج Dart: `hamnava`.
- نام اولیه مخزن `hamna` بود و اصلاح شده؛ پروژه جدیدی از صفر نساز.
- کد با Flutter/Dart نوشته شده و هدف فعلی فقط وب است.
- برای این معماری به سرور Apache، Node backend یا Cloud Functions نیاز نیست.
  Node فقط ابزار اختیاری انتشار و تست‌های فایربیس است.

## امکاناتی که در کد وجود دارند

- ثبت‌نام و ورود با ایمیل/رمز، خروج، بازیابی رمز و ارسال ایمیل تأیید.
- ساخت، ویرایش و حذف یادداشت، حال‌وهوا، برچسب، جستجو و بارگیری تاریخچه.
- ضبط میکروفون تا پنج دقیقه، تبدیل گفتار زنده به متن قابل ویرایش و خواندن متن.
- انتخاب زبان گفتار فارسی یا آلمانی؛ رابط خود برنامه فعلاً فارسی و راست‌به‌چپ است.
- ثبت مستقل درآمد و هزینه، دسته‌بندی، مبلغ یورو، تاریخ قابل تغییر، انتخاب ماه،
  مجموع‌ها و نمودار سهم دسته‌ها.
- پیشنهاد تراکنش از جمله فارسی با قواعد ساده؛ این هوش مصنوعی مالی نیست.
- خروجی JSON همه متن‌ها و تراکنش‌ها؛ دانلود صوت هر یادداشت به‌صورت جداگانه.
- طراحی کرم روشن، سبز عمیق و جزئیات مسی؛ ناوبری متناسب با موبایل و دسکتاپ.

### وضعیت قوانین زنده

کاربر قوانین ساده محدود به مالک را در کنسول منتشر کرده است. نسخه دقیق‌تر در
`firestore.rules`، علاوه بر مالکیت، نوع و طول فیلدها، مبلغ صحیح مثبت، دسته‌ها
و زمان‌ها را کنترل می‌کند. تست‌های این نسخه پاس شده‌اند، اما این Rules جدید
هنوز به پروژه زنده deploy نشده‌اند. اسکریپت انتشار آن‌ها را همراه Hosting می‌فرستد.

## صدا و داده محلی

- پیاده‌سازی مرورگر در `web/browser.js` و پل JS/Dart در `lib/platform/` است.
- فایل صوتی در IndexedDB همان مرورگر نگهداری می‌شود؛ به Firebase Storage
  آپلود نمی‌شود و روی دستگاه دیگر همگام نمی‌شود.
- حذف داده‌های مرورگر یا تغییر origin/پورت ممکن است دسترسی به صوت قبلی را از بین ببرد.
- متن پیش‌نویس در session storage و ورود به‌صورت محلی و ماندگار است؛ دادهٔ اصلی و تصاویر رسید در Firestore هستند.
- تبدیل گفتار از SpeechRecognition مرورگر استفاده می‌کند. پشتیبانی و کیفیت فارسی
  تضمین‌شده نیست و مرورگر ممکن است صدا را برای پردازش به سرویس خود بفرستد.
- این نسخه فایل صوتی قدیمی یا فایل واردشده را آفلاین به متن تبدیل نمی‌کند؛
  تبدیل در زمان گفتن انجام می‌شود. مدل محلی Whisper/Vosk اضافه نشده است.
- خواندن متن به صدای نصب‌شده دستگاه بستگی دارد؛ نبود صدای فارسی باید گزارش شود.
- سرویس صوتی پولی یا تضمین آفلاین بودن اضافه نکن.

## دیدن برنامه روی مک

نیازمندی: Flutter 3.35+ / Dart 3.9+؛ نسخه stable جدید مناسب است. کاربر گفته
Flutter نصب دارد. Chrome برای دستور زیر لازم است.

اگر هنوز پروژه دانلود نشده:

```bash
mkdir -p ~/Projects
cd ~/Projects
git clone https://github.com/Rezatajali/hamnava.git
cd hamnava
bash scripts/preview.sh
```

اگر قبلاً دانلود شده، داخل همان پوشه پروژه:

```bash
git pull
bash scripts/preview.sh
```

مرورگر باز می‌شود؛ برای استفاده حساب بساز یا وارد شو. این اجرای محلی است،
نه انتشار عمومی. برای قطع اجرا در Terminal کلید Control+C را بزن.
اگر Chrome موجود نیست، می‌توان از `flutter run -d web-server --web-port=8765`
استفاده کرد و آدرس نمایش‌داده‌شده را در Safari باز کرد؛ ضبط و صدا باید جداگانه تست شوند.

## انتشار و گرفتن لینک آنلاین

نسخهٔ قبلی روی Firebase Hosting منتشر شده است؛ برای این نسخهٔ جدید باید دوباره deploy انجام شود.
برای انتشار، Node.js 22+ و npm/npx روی مک لازم است. داخل پوشه پروژه:

```bash
bash scripts/deploy-firebase.sh
```

اسکریپت ابتدا analyze، test و build را اجرا می‌کند، سپس ورود رسمی Firebase را
باز می‌کند. کاربر باید با حساب گوگل مالک `hamnava-67a58` وارد شود. رمز، توکن یا
کلید service account از کاربر نخواه و در چت یا مخزن ثبت نکن.
بعد Rules و Hosting را فقط روی همین project ID منتشر می‌کند.
پس از موفقیت انتظار داریم آدرس زیر قابل استفاده شود:

https://hamnava-67a58.web.app

این لینک قبل از deploy به‌عنوان برنامه زنده معرفی نشود. انتشار Hosting به خرید
دامنه نیاز ندارد؛ محدودیت سهمیه رایگان همچنان برقرار است.

## کارهای باقی‌مانده برای ادامه‌دهنده

1. از `main` فعلی ادامه بده؛ اسم و فناوری یا پروژه Firebase را عوض نکن.
2. اجرای واقعی و ظاهر را روی مک و آیفون بررسی و خطاها را اصلاح کن.
3. ورود دو حساب را آزمایش کن؛ یادداشت و تراکنش A نباید در B دیده شوند.
4. ذخیره، refresh، ویرایش، حذف، خروجی و جمع ماه‌های مختلف را آزمایش کن.
5. کیفیت فارسی، مجوز میکروفون، توقف، پخش و دانلود را روی Safari/iPhone بررسی کن.
6. با ورود رسمی صاحب پروژه، Hosting و Rules را منتشر کن؛ لینک را بعد از
   انتشار باز کن و کارکرد واقعی را تأیید کن.
7. قبل از معرفی در رزومه، تصاویر واقعی رابط و توضیح محدودیت صدا را اضافه کن.

بومی‌سازی کامل آلمانی، تنظیم ارز، تقویم شمسی، حذف کامل حساب، بودجه‌بندی،
ورود فایل صوتی، اتصال بانکی و نسخه native هنوز پیاده‌سازی نشده‌اند. حساب پرداخت،
Storage یا سرویس پولی را برای حل مشکل خودکار فعال نکن.
